Choose the actual programs before interpreting them

The uniform graph theorem turns each primitive-recursive presentation into a total single-valued arithmetic graph. We now apply it to the square-pair list coding and the existing numerical syntax algorithms. Choosing a presentation is only the beginning: the identities needed by a checker must also be proved from that presentation's equations inside PA.

Throughout this entry, \(\operatorname{cons},\operatorname{head},\operatorname{tail},\operatorname{len},\operatorname{entry},\operatorname{append}\) name the specified programs below. The syntax operations are the actual tag recognizers, the history-based rewrite program and the recursive numeral constructor. They agree with the corpus's existing numerical routines on ordinary natural inputs. At nonstandard inputs they mean their chosen arithmetic graphs, not an arbitrary extension of those numerical functions.

We freely use their function abbreviations by conservativity of graph extensions. Consequently every identity stated as a PA theorem can be expanded into a closed sentence of the original arithmetic language. As in the model-to-derivation method, proofs in every PA-model give actual derivations of those closed sentences.

Recover both coordinates of the square-pair code

Retain the numerical square-pairing convention

\[\operatorname{pair}(a,b)=\begin{cases}b^2+a,&a\lt b,\\a^2+a+b,&b\le a.\end{cases}\]

The numerical decoding routine works as follows. To decode \(z\), find the largest \(r\le z\) with \(r^2\le z\). If \(z-r^2\lt r\), return \((z-r^2,r)\); otherwise return \((r,z-r^2-r)\). All differences are truncated subtraction, implemented by bounded recursion. The searches include their endpoints and use zero as their total default.

PA proves both coordinate inverse laws and reconstruction of every code:

\[\operatorname{left}(\operatorname{pair}(a,b))=a,\qquad\operatorname{right}(\operatorname{pair}(a,b))=b.\]
\[\operatorname{pair}(\operatorname{left}(z),\operatorname{right}(z))=z.\]

Proof

PA proves \(r^2\le z\lt(r+1)^2\) for the chosen \(r\). If the first branch holds, the proposed first coordinate is less than \(r\), so the first branch of pairing reconstructs \(z\). Otherwise \(z-r^2-r\le r\), since \(z\lt r^2+2r+1\); the second branch reconstructs \(z\). Conversely, when \(a\lt b\), the code lies between \(b^2\) and \(b^2+b\), so its square root is \(b\) and the first decoder branch returns \(a,b\). When \(b\le a\), the code lies between \(a^2+a\) and \(a^2+2a\), and the second branch returns \(a,b\). The case \(z=0\) gives both coordinates zero. These inequalities also prove that bounded search chooses the intended largest root. □

The same calculation proves that each coordinate is at most the original pair code. These bounds will justify all decreasing-code recursions below.

A nonempty list code exposes a strictly smaller tail

Set \(\operatorname{nil}=0\) and \(\operatorname{cons}(a,c)=1+\operatorname{pair}(a,c)\). At zero define both decoders to be zero; at a positive code \(c\), unpair \(c-1\). PA proves

\[\operatorname{head}(\operatorname{cons}(a,c))=a,\qquad \operatorname{tail}(\operatorname{cons}(a,c))=c.\]
\[c\ne0\;\longrightarrow\;c=\operatorname{cons}(\operatorname{head}(c),\operatorname{tail}(c))\ \land\ \operatorname{tail}(c)\lt c.\]

Proof

The inverse laws follow by the two coordinate identities. For a nonzero \(c\), PA's predecessor axiom gives its predecessor; pair reconstruction then gives the displayed constructor equation. The decoded tail is at most \(c-1\), hence strictly less than \(c\). These are statements about every internal number. We do not claim that repeatedly decoding a nonstandard code reaches zero in an externally finite number of steps. The induction arguments use the arithmetic inequality on codes instead. □

Compile a fold as a bounded iteration

The numerical bounded fold has the following internal construction. Suppose a program \(h(a,z)\) updates an accumulator \(z\) using one element \(a\). A traversal state is the pair of the unconsumed list code and the accumulator. One step leaves an empty-list state unchanged; otherwise it changes \((c,z)\) to \((\operatorname{tail}(c),h(\operatorname{head}(c),z))\). Iterate this step \(c\) times, starting at \((c,z)\), and return its accumulator. This is the specified \(\operatorname{fold}_h(c,z)\), built by ordinary primitive recursion on the allowance \(c\).

Why is the allowance enough inside PA? At each nonempty step the remaining code decreases by at least one. Induction on the allowance proves that a traversal with allowance at least its initial code has reached the empty-list state. Further steps leave it unchanged. This supplies the stability lemma needed to compare two different allowances.

The resulting PA equations are

\[\operatorname{fold}_h(0,z)=z,\]
\[\operatorname{fold}_h(\operatorname{cons}(a,c),z)=\operatorname{fold}_h(c,h(a,z)).\]

For the second equation, take one actual state step, then compare its remaining allowance with the allowance used in the right-hand definition. Both are sufficient for the tail; stability makes their results equal. Merely asserting that the tail decreases would prove external termination, but would omit this equality between the actual bounded programs.

A fixed parameter \(p\) is carried in the accumulator as \(\operatorname{pair}(p,z)\). Each update preserves its first coordinate and changes the second. Strong induction on the list code proves that the parameter remains \(p\). Unpairing the final state gives a parameterized fold with the same equations.

Build the familiar list operations from the fold

For the actual append and length and entry routines, PA proves

\[\operatorname{append}(0,d)=d,\]
\[\operatorname{append}(\operatorname{cons}(a,c),d)=\operatorname{cons}(a,\operatorname{append}(c,d)).\]

The length equations are \(\operatorname{len}(0)=0\) and \(\operatorname{len}(\operatorname{cons}(a,c))=S\operatorname{len}(c)\). The entry equations are \(\operatorname{entry}(\operatorname{cons}(a,c),0)=a\) and \(\operatorname{entry}(\operatorname{cons}(a,c),Si)=\operatorname{entry}(c,i)\). No in-range hypothesis is needed: the total default is zero after exhaustion.

Proof

Folding with the constructor reverses a list onto its initial accumulator. Let \(\operatorname{rev}\) denote that operation starting at zero; define append by reversing once and folding the reversed result onto the second list. Use the stronger fusion invariant: folding a list already obtained by constructor-folding \(c\) onto \(x\) agrees with folding \(x\) onto the fold of \(\operatorname{rev}(c)\). Strong induction on \(c\) proves this invariant from the fold equation. Its empty and constructor cases, specialized to the append definition, give the displayed append equations.

For length, fold with \(h(a,z)=Sz\) and start at zero. Strong induction on \(c\) proves \(\operatorname{fold}_h(c,Sz)=S\operatorname{fold}_h(c,z)\). The empty fold and the constructor fold, together with this invariant, give the stated length equations.

For entries, iterate tail \(i\) times and then take head. At zero use head of a constructor. At a successor, one tail operation removes the constructor, and the remaining iteration is exactly the iteration on its tail. These are the entry equations above, including all out-of-range indices. □

A history lets a recursive clause read every smaller input

The numerical history construction becomes an internal program as follows. A syntax routine may need the answers at several children of its current code, rather than just at the preceding integer. For a fixed step program \(h(\bar p,e,H)\), define a history \(H(\bar p,e)\) containing the answers at inputs below \(e\), in increasing order:

\[H(\bar p,0)=0,\]
\[H(\bar p,Se)=\operatorname{append}(H(\bar p,e),[h(\bar p,e,H(\bar p,e))]).\]

Here \([a]\) abbreviates \(\operatorname{cons}(a,0)\). Define the answer at \(e\) to be \(h(\bar p,e,H(\bar p,e))\). Ordinary primitive recursion constructs the history program, since append is already available.

Proof

Induct on the history length. The invariant is that its length is \(e\), and its entry at every \(j\lt e\) is the answer at \(j\). The empty case is immediate. Appending the singleton preserves every earlier entry and installs the new answer at index \(e\). Consequently a step that reads a child \(j\lt e\) receives the actual recursively defined answer, not an arbitrary table entry. The quantifier over earlier indices is bounded and the whole invariant is arithmetic. It therefore applies also to nonstandard \(e\). □

Recognize syntax by recording four facts about each child

Use the existing tagged syntax: free names, bound slots, arithmetic function applications, equality, falsity, implication, universal quantification and auxiliary constants all have their specified tags. A node code is one plus the pair of its tag and its argument-list code. Each numerical child is smaller than the whole node, even though a node's tag or symbol index is only data and must not be recursively interpreted as a child.

Write \((T(a),F(a),U(a),V(a))\) for the summary stored at code \(a\): term-depth, formula-depth, free-name flag and auxiliary-name bound. Zero term-depth or formula-depth means that constructor kind is invalid. A valid depth is one more than the required number of available slots. The free-name flag is zero precisely when no free-name leaf occurs; auxiliary bound zero similarly excludes every auxiliary leaf.

The actual clauses are displayed below. For each compound row, every indicated term or formula child must have positive depth of the required kind; otherwise the summary is invalid. Arithmetic applications also check their fixed symbol and arity. Let \(M_U(a,b)=\max(U(a),U(b))\), and define \(M_V\) in the same way.

For requested available depth \(n\), the term or formula test requires its stored depth to be nonzero and at most \(n+1\). These Boolean tests are exactly the ones used by the numerical syntax recognizer. The extra free-name and auxiliary tests distinguish original-language sentences from recognized extended syntax.

Proof

The child-code bound has an internal version: every in-range entry of a node's argument list is smaller than the complete node. Unfold one actual summary-history step. The history lookup invariant identifies each child entry with its own summary, giving the displayed clauses. Conversely, the recognition cases decompose every code with positive depth into one of the valid listed constructors; all other tags and wrong arities are rejected. Strong induction on the numerical code therefore justifies the clauses even at nonstandard recognized codes. Symbol and tag data are checked directly, rather than treated as recursive children. □

Substitution preserves recognition, with its depth unchanged

Let \(\operatorname{Sub}(n,a,i,t)\) be the actual capture-safe free-name substitution routine. PA proves: if \(a\) is recognized as a formula with \(n\) available bound slots and \(t\) is recognized as a term with no unbound quantified slots, then \(\operatorname{Sub}(n,a,i,t)\) is recognized at the same depth.

Proof

First expose the actual rewrite clauses. A free-name leaf numbered \(i\) is replaced by \(t\); another free-name leaf remains unchanged. Bound slots and auxiliary constants are unchanged. At a compound node, preserve its tag and symbol data and recursively rewrite just its children. The history invariant identifies every rewritten child with the value of the same rewrite program at that smaller code.

Strong induction proves a simultaneous invariant for terms and formulas: a successful input keeps its constructor kind and its required bound depth, provided the replacement has no unbound quantified slots. For a replaced free leaf, the replacement needs zero available slots, so it introduces no dangling slot. At a function, equality or implication node, use the induction hypotheses on the children and the corresponding maximum-depth clauses. At a universal quantifier, the child already has one additional available slot; the same depth invariant leaves the bound-slot condition valid. Finally unfold the guarded substitution program: for recognized inputs the guard selects this rewrite, giving the stated conclusion. For malformed inputs it retains its specified total default. □

A depth-zero term may still contain free names or auxiliary constants; the tests for their absence are separate. Numerals satisfy those additional tests, as shown below. This theorem concerns substitution of free names. The bound-slot instantiation routine uses a different rewrite mode. It replaces the selected bound slot and shifts larger slot indices down. In this level-style slot convention, the same selected slot is used when traversing a quantifier; one does not increase it with the syntactic nesting depth. The common history implementation handles both, but their scope equations must be checked separately. A substitution proof does not by itself establish an instantiation identity.

Numerals are closed, and original formulas contain no auxiliary name

PA proves that the actual numeral constructor returns a term needing zero available bound slots, with no free-name leaves and no auxiliary constants. Its full summary is \((1,0,0,0)\).

Proof

The constructor equations are \(\operatorname{num}(0)=\ulcorner0\urcorner\) and \(\operatorname{num}(Sn)=\ulcorner S\urcorner(\operatorname{num}(n))\). Induct in PA on the single arithmetic assertion that its summary is \((1,0,0,0)\). The zero clause gives the base. The successor clause retains all four fields of the valid previous numeral, so the same tuple gives the step. Its term-depth proves recognition at depth zero; its third field excludes free names; its fourth excludes auxiliary names. This proves all three properties together, including at nonstandard numeral-construction inputs.

The actual auxiliary-occurrence test is another history program. At an auxiliary leaf it compares the leaf's index with the requested name; at other constructors it combines the child results by Boolean disjunction. Its induction invariant says: if a recognized original-language expression has auxiliary bound zero, the occurrence test returns zero for every requested auxiliary index. A recognized original sentence therefore contains no auxiliary constant, even when its code or the requested index is nonstandard.

This supplies a useful freshness fact without claiming that arbitrary proof contexts are fresh. When a proof rule introduces an auxiliary constant, the checker must also test the formulas in its actual context. That is a separate use of the list traversal and the occurrence routine; it cannot be replaced by the assertion that the conclusion alone is an original sentence. □

Which facts survive at a nonstandard syntax code?

A nonstandard PA-model contains codes that are not codes of any external finite formula. Which arguments in this entry still apply if its internal recognizer accepts such a code?

Show answerHide answer

The program equations, decreasing-child inequalities, recognition clauses, substitution preservation and freshness implications all still apply. They were proved by induction on arithmetic formulas and converted to PA theorems. What is not justified is external induction on a nonexistent finite parsed formula. The history program and strong induction on its numerical input replace that argument. Nor may one substitute another program merely because it agrees on standard codes: its internal equations require a comparison proof.
