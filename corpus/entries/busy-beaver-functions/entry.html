Measure the amount of program text

Use the ordinary paired-input programs, their evaluation \(E(c,x)\), and their numerical indices \(\#c\). The size \(|c|\) of a program is its number of syntax nodes:

\[|\mathsf{zero}|=|\mathsf{succ}|=|\mathsf{left}|=|\mathsf{right}|=1.\]
\[|\mathsf{pair}(c,d)|=|\mathsf{comp}(c,d)|=|\mathsf{prec}(c,d)|=1+|c|+|d|,\qquad |\mathsf{find}'(c)|=1+|c|.\]

This is a total computable function of \(\#c\), by structural recursion on program codes. Every program has positive size. Repeated subprograms count each time they occur: the syntax is a tree, without shared subroutines. This convention fixes the meaning of the size parameter in all the maxima below.

A size bound gives an effectively known finite list

For every \(n\), the set \(\mathcal C_n=\{c:|c|\le n\}\) is finite. There is one total computable procedure producing a finite list with exactly these programs, and \(\mathcal C_n\subseteq\mathcal C_{n+1}\).

Start with the empty list at \(n=0\). From a list for \(\mathcal C_n\), form the four leaves, all programs \(\mathsf{find}'(c)\) with \(c\) in that list, and all programs \(\mathsf{pair}(c,d),\mathsf{comp}(c,d),\mathsf{prec}(c,d)\) with both children in that list. Retain exactly those whose computed size is at most \(n+1\). This finite operation produces a list for \(\mathcal C_{n+1}\); repetitions, if any, can be removed by comparing numerical codes.

The induction assertion is equality with the specified set. Every generated program passes the size test. Conversely, a nonleaf of size at most \(n+1\) has each child of size at most \(n\), so the induction hypothesis places its children on the preceding list, and the corresponding constructor generates it. The four leaves cover the remaining case. Coded finite lists, their finite products and the constructor operations are computable, so recursion on \(n\) gives the claimed uniform procedure. Inclusion follows directly from the size inequality.

Use the least successful evaluation allowance

Write \(b(k,e,x)\) for the primitive-recursive bounded output code: zero means no result at allowance \(k\), and \(y+1\) means output \(y\). Thus \(\varphi_e(x)\downarrow\) exactly when \(b(k,e,x)>0\) for some \(k\), and increasing \(k\) preserves a successful output. The least successful resource of a halting program \(c\), at input zero, is

\[\lambda(c)=\min\{k:b(k,\#c,0)>0\}.\]

The minimum exists under the stated halting hypothesis. We leave \(\lambda(c)\) undefined when \(E(c,0)\) is undefined. The allowance belongs to this bounded evaluator; it is not a count of tape-machine transitions.

Maximize outputs and successful resources

The output Busy Beaver function \(B:\mathbb N\to\mathbb N\) and the resource Busy Beaver function \(S:\mathbb N\to\mathbb N\), for the present program-size convention, are

\[B(n)=\max\bigl(\{0\}\cup\{y:\exists c\in\mathcal C_n\;E(c,0)\downarrow=y\}\bigr).\]
\[S(n)=\max\bigl(\{0\}\cup\{\lambda(c):c\in\mathcal C_n,\ E(c,0)\downarrow\}\bigr).\]

Both maxima exist: gives finitely many candidates, each halting candidate has one output and one least successful resource, and the included zero makes each set nonempty. This defines total mathematical functions without claiming an algorithm for their values. Other programming languages and size conventions give different numerical functions; the present definitions use the previously fixed syntax throughout.

Every halting contestant is bounded by the maximum

The functions \(B\) and \(S\) are nondecreasing, \(B(0)=S(0)=0\), and for every program \(c\) with \(|c|\le n\) and \(E(c,0)\downarrow=y\),

\[y\le B(n),\qquad \lambda(c)\le S(n),\qquad b(S(n),\#c,0)=y+1.\]

Enlarging \(n\) retains every old contestant, proving both monotonicity assertions. There are no size-zero programs, so the two sets defining the maxima at zero consist just of zero. The first two displayed inequalities follow because the indicated values occur in the finite sets being maximized. At allowance \(\lambda(c)\), bounded evaluation succeeds with output \(y\); since \(\lambda(c)\le S(n)\), preservation of successful bounded evaluations gives the last equality.

Collect the successes visible by a finite stage

The finite-stage output maximum and finite-stage resource maximum are

\[B_s(n)=\max\bigl(\{0\}\cup\{b(s,\#c,0)-1:c\in\mathcal C_n,\ b(s,\#c,0)>0\}\bigr),\]
\[S_s(n)=\max\bigl(\{0\}\cup\{\min\{k\le s:b(k,\#c,0)>0\}:c\in\mathcal C_n,\ b(s,\#c,0)>0\}\bigr).\]

Every inner minimum is taken only for a candidate already successful at \(s\), so its finite search is nonempty. The subtractions occur only on positive output codes, including code one for numerical output zero.

Computable lower estimates eventually give the exact answer

The functions \((s,n)\mapsto B_s(n)\) and \((s,n)\mapsto S_s(n)\) are jointly total computable. For fixed \(n\), each is nondecreasing in \(s\), bounded by its corresponding Busy Beaver value, and eventually equal to it.

Compute the finite candidate list, carry out bounded evaluation, and take finite maxima. For \(S_s\), the additional search is bounded by \(s\). These are terminating procedures uniform in \(s,n\). Once a candidate succeeds, all later stages give the same output. Its first successful resource is then already among the searched values, so that resource also stays fixed. Thus later stages retain every previously contributing value; neither maximum decreases or exceeds its unrestricted maximum.

For fixed \(n\), take the maximum of the least successful resources of its finitely many halting contestants, including zero. At that stage every halting contestant has appeared. No other contestant ever contributes. Both finite-stage maxima therefore equal \(B(n)\) and \(S(n)\), respectively, at every later stage. This is an existence proof of a final stage, using knowledge of which contestants halt.

Count the digits needed for a constant

The binary length \(L(n)\) is specified by \(L(0)=0\) and

\[L(n)=1+L(\lfloor n/2\rfloor)\qquad(n>0).\]

Each recursive argument is smaller than its positive input, so the definition terminates and is computable. For \(n>0\), induction on successive division by two gives

\[2^{L(n)-1}\le n<2^{L(n)}.\]

Indeed, division writes \(n=2k+r\) with \(r\in\{0,1\}\). When \(k=0\), positivity forces \(n=1\). Otherwise doubling the bounds for \(k\), and allowing the last digit \(r\), gives the displayed bounds for \(n\). These inequalities also show that binary length tends to infinity with \(n\).

Construct a numeral with only linearly many nodes in its binary length

There is a total computable map \(n\mapsto C(n)\) into the existing program syntax and a fixed positive integer \(a\) such that, for every \(n,x\),

\[E(C(n),x)=n,\qquad |C(n)|\le 1+aL(n).\]

Fix a program \(D\) computing \(z\mapsto2z\); one exists by primitive-recursive addition and program completeness. Write \(d=|D|\). Define actual program trees by

\[C(0)=\mathsf{zero},\qquad C(2k)=\mathsf{comp}(D,C(k))\quad(k>0),\]
\[C(2k+1)=\mathsf{comp}(\mathsf{succ},\mathsf{comp}(D,C(k))).\]

The second and third rules cover the positive even and odd inputs, respectively. Strong induction on \(n\) proves the asserted evaluation identity for every runtime input \(x\): the recursive program first returns \(k\), doubling returns \(2k\), and the outer successor, when present, returns \(2k+1\). Every intermediate computation terminates.

The even rule adds \(d+1\) nodes and the odd rule adds \(d+3\). Taking \(a=d+3\), the induction hypothesis and \(L(n)=1+L(k)\) give \(|C(n)|\le1+aL(n)\); at zero this is equality. To compute the numerical code, successively divide \(n\) by two, retain the remainders, and rebuild the tree from zero using the corresponding rule in reverse order. The list of quotients strictly decreases until zero. Finite-list processing and the effective constructor operations prove total computability of this specified compiler.

For example, the digits of five are \(101\). Beginning with zero, the rules successively form the constant programs for \(1\), \(2\), and \(5\); each new digit inserts one copy of \(D\) and at most one successor. The ordinary unary constant compiler from the parameter theorem is correct as well, but its repeated successors do not give the binary-length bound proved here.

A fixed program and a binary constant eventually fit the input budget

For any fixed natural numbers \(u,v\), there is \(N\) such that \(u+vL(n)\le n\) whenever \(n\ge N\).

For every \(j\ge4\), \(2^j\ge j^2\). The case \(j=4\) is equality, and the induction step follows from \(2j^2\ge(j+1)^2\) for \(j\ge3\). Choose \(\ell_0\ge5\) and \(\ell_0\ge2(u+v+1)\). When \(\ell\ge\ell_0\), elementary multiplication gives \(u+v\ell\le(u+v)\ell\le(\ell-1)^2\). Taking \(N=2^{\ell_0-1}\), the binary-length bounds give \(L(n)\ge\ell_0\) for \(n\ge N\). Consequently

\[u+vL(n)\le(L(n)-1)^2\le2^{L(n)-1}\le n.\]

This proves the budget estimate using only the displayed elementary inequalities.

The output maximum eventually exceeds every computable function

For every total computable \(f:\mathbb N\to\mathbb N\), there is \(N\) such that

\[B(n)>f(n)\qquad\text{for every }n\ge N.\]

Fix a program \(p\) computing \(x\mapsto f(x)+1\), using computable composition and program completeness. The specified program \(P_n=\mathsf{comp}(p,C(n))\) halts at input zero with output \(f(n)+1\). Its size satisfies

\[|P_n|=1+|p|+|C(n)|\le |p|+2+aL(n).\]

By , this is at most \(n\) for all sufficiently large \(n\). For each such \(n\), \(P_n\) is one of the contestants defining \(B(n)\), so \(f(n)+1\le B(n)\). This proves the strict inequality, with the one fixed program \(p\) and the single constant compiler working for every \(n\).

No computable function is even an eventual upper bound

The function \(B\) is not computable. There is no total computable \(g\) and no \(N\) with \(B(n)\le g(n)\) for every \(n\ge N\).

Such a \(g\) is eventually strictly smaller than \(B\), by , contradicting the proposed eventual upper bound. If \(B\) itself were computable, take \(g=B\) to obtain the same contradiction.

Represent a natural-valued oracle by its graph

For a total function \(f:\mathbb N\to\mathbb N\), its graph oracle is the set

\[G_f=\{\langle x,y\rangle:f(x)=y\}\subseteq\mathbb N.\]

To say that \(f\) is computable from an oracle \(A\) means that one of the actual oracle programs evaluates under \(A\) to \(f(x)\) for every \(x\). The Turing degree of \(f\) is the degree of \(G_f\), using the established degree convention for sets. The following bridges connect these two formulations.

A graph query and function evaluation compute each other

For every total \(f\), one fixed oracle program, independent of \(f\), computes \(f(x)\) under the graph oracle \(G_f\). For every oracle \(A\),

\[f\text{ is computable from }A\quad\Longleftrightarrow\quad G_f\le_T A.\]

On input \(x\), query \(\langle x,0\rangle,\langle x,1\rangle,\ldots\) and return the first \(y\) answered yes. Exactly one query is positive, namely \(y=f(x)\); all earlier queries terminate, and the search therefore returns exactly \(f(x)\). In the existing oracle syntax this is \(\mathsf{find}'(\mathsf{comp}(\mathsf{not},\mathsf{query}))\) on input \(\langle x,0\rangle\), where \(\mathsf{not}\) is the ordinary zero-test program: it returns zero on a positive membership answer and one on a negative answer. Prepending the ordinary map \(x\mapsto\langle x,0\rangle\) gives the one fixed lookup program.

If an \(A\)-oracle program \(c\) computes \(f\), a graph decider on input \(z=\langle x,y\rangle\) runs \(c\) at \(x\), compares its output with \(y\), and returns the resulting zero-one equality bit. Ordinary projections, pairing and equality tests are computable, and oracle composition builds this actual oracle program from \(c\). It terminates because \(f\) is total and returns the characteristic bit of the same set \(G_f\).

Conversely, given an actual reduction program for \(G_f\le_T A\), substitute that total membership program for every query in the fixed lookup program. The substitution identity gives an \(A\)-oracle program returning \(f(x)\). Thus both directions refer to programs in the established language and to this specified graph encoding.

A halting oracle computes both finite maxima

The graph sets satisfy \(G_B\le_T K\) and \(G_S\le_T K\), where \(K=\{e:\varphi_e(e)\downarrow\}\).

Define the ordinary input-freezing compiler

\[F(e,x)=\#\mathsf{comp}(c_e,C(x)).\]

It is total computable and \(\varphi_{F(e,x)}(z)\simeq\varphi_e(x)\) for every runtime input \(z\), by the constant-program identity. In particular, \(F(e,x)\in K\) if and only if \(\varphi_e(x)\downarrow\).

On input \(n\), compute the finite list \(\mathcal C_n\). For each candidate \(c\), query whether \(F(\#c,0)\in K\). If the answer is negative, contribute zero. If it is positive, search the total bounded test \(b(k,\#c,0)>0\) for its least successful \(k\). This search terminates exactly in the positive case. Its value is \(\lambda(c)\), and \(b(k,\#c,0)-1\) is the output. Fold the list, retaining the largest resource and largest output seen so far, starting both accumulators at zero.

The fold invariant is that the accumulators are the two maxima over the processed candidates, together with zero. The negative branch omits precisely the divergent candidate; the positive branch inserts precisely its unique output and least resource. Induction through the finite list therefore gives exactly \(B(n),S(n)\). All branches terminate under \(K\). The operations are ordinary computable operations, one total oracle membership call, a conditional least-witness search and finite recursion; the established closure theorem yields actual \(K\)-oracle programs for the two functions. Applying gives the stated graph reductions.

A resource upper bound decides whether a computation halts

For every total function \(h\) with \(S(n)\le h(n)\) for all \(n\), one has \(K\le_T G_h\). In particular \(K\le_T G_S\).

Given \(e,x\), compute the frozen program \(p=\mathsf{comp}(c_e,C(x))\) from , and its size \(n=|p|\). Retrieve \(h(n)\) using the fixed graph lookup program, then test \(b(h(n),\#p,0)>0\). If \(\varphi_e(x)\) halts, then \(p\) halts and its least successful resource is at most \(S(n)\le h(n)\); monotonicity makes the test positive. If the test is positive, bounded-evaluation correctness makes \(p\) halt, hence makes \(\varphi_e(x)\) halt. Thus this terminating test decides the full halting relation. Supplying \(x=e\) decides \(K\).

The numerical compiler, size calculation and bounded test are ordinary total computable functions. Compose their ordinary programs with the one graph lookup program, and take the positive-test bit. Oracle composition gives an actual reduction program for \(K\le_T G_h\), without needing an effective procedure to verify the upper-bound hypothesis.

A program can output the first certificate for another computation

There is one total computable compiler \((e,x)\mapsto q(e,x)\) into ordinary program indices such that, for every runtime input \(z\),

\[\varphi_{q(e,x)}(z)\simeq\min\{k:b(k,e,x)>0\}.\]

The right side is undefined when no such \(k\) exists. In particular, the compiled program halts exactly when \(\varphi_e(x)\) does, and in that case outputs its least successful resource.

The bounded test is total computable jointly in \(k,e,x\). Least-witness search makes the right side partial recursive jointly in \(e,x\), by the search rule. Choose one ordinary program \(r\) whose input \(\langle e,x\rangle\) computes this partial function. Using , set

\[q(e,x)=\#\mathsf{comp}(r,C(\langle e,x\rangle)).\]

The compiler merely constructs this finite syntax, so is total computable even for a divergent original computation. The inner program returns the specified pair on every \(z\); the outer program then performs the stated least-witness search. This proves the exact partial-value identity, including divergence.

An output upper bound also supplies a halting deadline

For every total function \(h\) with \(B(n)\le h(n)\) for all \(n\), one has \(K\le_T G_h\). In particular \(K\le_T G_B\).

Given \(e,x\), compute \(q=q(e,x)\), its decoded program \(c_q\), and \(n=|c_q|\). Retrieve \(h(n)\) from its graph oracle and test the original computation by \(b(h(n),e,x)>0\). If \(\varphi_e(x)\) halts, let \(k\) be its least successful resource. The compiler lemma says that \(c_q\), at input zero, outputs exactly \(k\). Therefore

\[k\le B(|c_q|)\le h(n).\]

Preservation of successful bounded evaluations makes the test positive. Conversely, a positive bounded test is already a certificate that \(\varphi_e(x)\) halts. Again \(x=e\) gives the characteristic bit of \(K\). The same ordinary-preprocessing, graph-lookup and bounded-test composition used for is an actual oracle program for this reduction.

The argument does not identify outputs with running resources. It uses a program deliberately compiled to output the resource witness; its size determines which value of the output bound is queried.

Both Busy Beaver functions have exactly the halting degree

With the specified graph encoding,

\[G_B\equiv_T K\equiv_T G_S.\]
