The parameter program retains both numerical inputs

Use the oracle program numbering \(\varphi_e^A(x)\simeq E_A(c_e,x)\), its constant programs \(C_a\), identity program \(I\), and specified parameter map

\[s(e,a)=\#\operatorname{comp}\bigl(c_e,\operatorname{pair}(C_a,I)\bigr).\]

The constant-code map \(a\mapsto\#C_a\) is injective, and \(s\) is jointly injective:

\[s(e,a)=s(f,b)\quad\Longrightarrow\quad e=f\ \text{ and }\ a=b.\]

If two constant programs have the same syntax, evaluate them at input zero with the empty oracle. Their outputs are their respective constants, so those constants agree. Equality of their numerical codes implies equality of the programs because coding is injective. Next decode an equality of specialized codes. The outer composition constructors agree, so their first children give \(c_e=c_f\) and hence \(e=f\). Equality of their second children gives \(C_a=C_b\), hence \(a=b\). This argument concerns the actual finite syntax; distinct programs may still compute the same function.

Insert a tag that the program discards at runtime

Write \(\operatorname{Comp}(e,d)=7+4\langle e,d\rangle\) for the numerical composition constructor. Code three denotes the right projection \(\mathbf R\). Define the oracle padding map by

\[p(e,t)=s\bigl(\operatorname{Comp}(e,3),t\bigr).\]

Its decoded program is exactly

\[\operatorname{comp}\bigl(\operatorname{comp}(c_e,\mathbf R),\operatorname{pair}(C_t,I)\bigr).\]

The inner pairing forms \(\langle t,x\rangle\). The right projection removes the tag, leaving \(x\) for \(c_e\). All choices in this construction are numerical and are made before supplying an oracle.

One injective padding map preserves computations for every oracle

The specified \(p:\mathbb N^2\to\mathbb N\) is ordinary primitive recursive and jointly injective. For every oracle \(A\) and all \(e,t,x\),

\[\varphi_{p(e,t)}^A(x)\simeq\varphi_e^A(x).\]

The composition constructor and \(s\) are ordinary primitive recursive, so their displayed composition is primitive recursive. If \(p(e,t)=p(f,u)\), joint injectivity of \(s\) gives \(t=u\) and \(\operatorname{Comp}(e,3)=\operatorname{Comp}(f,3)\). Injectivity of pairing gives \(e=f\).

For evaluation, parameter insertion gives

\[\varphi_{p(e,t)}^A(x)\simeq E_A\bigl(\operatorname{comp}(c_e,\mathbf R),\langle t,x\rangle\bigr)\simeq E_A(c_e,x).\]

The first two operations always terminate and pass exactly \(x\) to the old program. Thus the identity preserves every defined output and every divergence. No property of \(A\) was used; it is the same numerical map for all oracles, not a separately chosen map for each one.

Every oracle program has infinitely many equivalent names

For each \(e\), the set of indices \(j\) satisfying \(\varphi_j^A(x)\simeq\varphi_e^A(x)\) for every \(A,x\) is infinite. The specified total computable injection \(t\mapsto p(e,t)\) enumerates a subset of it.

Two equal outputs of this map have equal tags by joint injectivity. Every output has the required all-oracle behavior by . An injective image of \(\mathbb N\) is infinite. This includes a program that diverges everywhere: the padding construction never needs to wait for the old program to halt.

Choose the least padded name outside a finite list

Let \(l\) be the numerical code of a finite list \(L\) of forbidden indices, and put \(m=|L|\). Define the escaping tag and fresh padded index by

\[\tau(e,l)=\min\{t\le m:p(e,t)\notin L\},\qquad q(e,l)=p(e,\tau(e,l)).\]

The minimum exists. The \(m+1\) names \(p(e,0),\ldots,p(e,m)\) are distinct, whereas a list of length \(m\) contains at most \(m\) distinct numbers. Thus at least one candidate is absent. Repeated forbidden entries cause no difficulty, and the empty list selects tag zero.

Finite avoidance is an ordinary bounded computation

The specified maps \(\tau\) and \(q\) are ordinary primitive recursive. For every \(e,l\), the chosen tag is at most \(|L|\), its padded index is absent from \(L\), and every earlier tag gives a member of \(L\). Moreover,

\[\varphi_{q(e,l)}^A(x)\simeq\varphi_e^A(x)\qquad\text{for every }A,x.\]

Decoding the finite list, obtaining its length, computing a padded code, and testing membership in the list are primitive recursive. Apply the established bounded-search construction to tags below \(m+1\). The existence argument in ensures that this search finds a successful tag rather than returning its failure bound. Its least-success guarantee gives all the stated finite-list properties. Composing with \(p\) computes \(q\); its evaluation identity follows from . The algorithm compares program numbers, without evaluating their represented functions or asking an oracle question.

Freezing an input also retains the old program and input injectively

The existing input-freezing map

\[f(e,x)=\#\operatorname{comp}(c_e,C_x)\]

is jointly injective in \((e,x)\). Consequently \(x\mapsto f(e,x)\) is an ordinary primitive-recursive injection for every fixed \(e\), and it obeys the existing identity

\[\varphi_{f(e,x)}^A(y)\simeq\varphi_e^A(x)\qquad\text{for every }A,y.\]

Decode equality of two frozen codes. The first children of the composition give equality of the old program codes. The second children are equal constant programs, whose values recover the frozen inputs by . This proves joint injectivity. Primitive recursiveness and the full evaluation identity are the input-freezing theorem. In contrast to padding, freezing deliberately replaces the runtime input by a specified fixed input; that distinction is essential when the new code itself will later be used as an input.

The relative jump is complete under ordinary injective maps

For every oracle \(A\) and set \(S\subseteq\mathbb N\),

\[S\text{ is }A\text{-c.e.}\quad\Longleftrightarrow\quad S\le_1 J(A),\]

where a one-one reduction uses a total ordinary computable injection. For each domain index \(e\), the specified map \(x\mapsto f(e,x)\) gives this reduction for \(W_e^A\), with the same map for every oracle.

If \(S\) is \(A\)-c.e., choose its oracle domain index \(e\). Input freezing gives \(x\in S\Longleftrightarrow f(e,x)\in J(A)\), and proves that this very map is injective and ordinary computable. This works also for finite and empty domains. Conversely a one-one reduction is in particular an ordinary many-one reduction; the relative completeness theorem then puts \(S\) in the \(A\)-c.e. class. The recognizer for \(S\) may use \(A\), but the translation of a numerical input into its new program code does not.

Separate zero-input halting from diagonal halting

The relative zero-input halting set is

\[Z(A)=\{e:\varphi_e^A(0)\downarrow\}.\]

It uses the same oracle program numbering as \(J(A)=\{e:\varphi_e^A(e)\downarrow\}\), but a different runtime input. Define the diagonal-to-zero map and zero-to-diagonal map by

\[u(e)=f(e,e),\qquad v(e)=f(e,0).\]

Both maps freeze the old input before changing the program's name. Their definitions contain no reference to \(A\).

The same two injective recodings work for all oracles

The specified \(u,v\) are ordinary primitive-recursive injections and satisfy, for every oracle \(A\) and every \(e\),

\[e\in J(A)\Longleftrightarrow u(e)\in Z(A),\qquad e\in Z(A)\Longleftrightarrow v(e)\in J(A).\]

Thus \(J(A)\) and \(Z(A)\) are one-one equivalent for each \(A\).

Primitive recursiveness follows by composing \(f\) with duplication or with the constant zero. If two outputs of either map agree, joint injectivity of \(f\) recovers their first coordinates, proving injectivity. Finally the two required computations are exactly

\[\varphi_{u(e)}^A(0)\simeq\varphi_e^A(e),\qquad \varphi_{v(e)}^A(v(e))\simeq\varphi_e^A(0).\]

Taking definedness gives the displayed equivalences. The second identity evaluates the new program at its own new index; input freezing is what ensures that this still runs the old program at zero. The construction and both proofs use the same numerical maps for all oracles.

Does computing a new code require the oracle used when running it?

Why is ordinary computability of the padding and freezing maps stronger than merely allowing a computation to ask the supplied oracle? Must every total function computable with oracle \(A\) be ordinary computable?

Show answerHide answer

No. The function \(x\mapsto\chi_A(x)\) is computed with oracle \(A\) by the single query instruction. If \(A\) is not computable, this characteristic function is not ordinary computable, since it would otherwise decide membership in \(A\).

The maps here only assemble finite syntax from natural numbers, so ordinary algorithms compute their outputs without learning any membership bit of \(A\). Running the resulting program may then make oracle queries. For example, padding the query program gives \(\varphi_{p(4,t)}^A(x)=\chi_A(x)\) for every \(A,t,x\), although computing the number \(p(4,t)\) itself needs no oracle.

Do different tags give different partial functions?

For fixed \(e\), joint injectivity gives \(p(e,0)\ne p(e,1)\). Does this force the two programs to compute different partial functions for some oracle?

No. Their indices are distinct, but makes both compute exactly \(\varphi_e^A\) for every oracle \(A\). They agree on every input, including simultaneous divergence. Even for the query program, whose values depend on the oracle, changing the padding tag changes none of its behavior under that oracle. Freshness is a statement about finite program names; the construction was designed to preserve their partial functions.
