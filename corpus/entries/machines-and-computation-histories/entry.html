A machine with a numbered state

A computation changes a finite amount of recorded information according to a fixed rule. We represent its whole configuration by a natural number. A pair, a finite list, a counter and a list of pending tasks can all be stored using the codes for finite data.

An arithmetic machine is a quadruple \(M=(I,D,H,O)\). Its initialization \(I:\mathbb N\to\mathbb N\), transition \(D:\mathbb N\to\mathbb N\), halt test \(H:\mathbb N\to\{0,1\}\), and output \(O:\mathbb N\to\mathbb N\) are all primitive recursive. A program includes a finite primitive-recursive construction of these four functions. Thus it is a finite recipe, rather than an arbitrary choice of four functions.

At input \(x\), start in \(I(x)\). If \(H(c)=1\), halt with output \(O(c)\); otherwise replace \(c\) by \(D(c)\). A transition is a macro step: it may perform a bounded loop or decode a list. We are measuring which outputs eventually exist, not the time taken by elementary instructions. This is a specific model of computation; no tape, register instruction set or informal notion of algorithm is hidden in its definition.

A machine that doubles its input

Write \(\langle r,a\rangle\) for the square-pairing code. Consider

\[I(x)=\langle x,0\rangle,\quad D\langle r,a\rangle=\langle r\mathbin{\dot-}1,a+2\rangle,\quad H\langle r,a\rangle=\chi_{r=0},\quad O\langle r,a\rangle=a.\]

What happens at inputs \(3\) and \(0\)? Does the transition rule keep adding two after the counter reaches zero?

The successive configurations at input \(3\) are \(\langle3,0\rangle,\langle2,2\rangle,\langle1,4\rangle,\langle0,6\rangle\). The machine then halts with output \(6\). At input \(0\) it halts immediately in \(\langle0,0\rangle\), with output zero. It never applies \(D\) to a halted state. More generally, after \(i\le x\) steps the two counters are \(x-i\) and \(2i\), by induction, so the output is \(2x\). Pairing, its projections, truncated subtraction, addition and the zero test are primitive recursive, making this an arithmetic machine.

Run for a prescribed number of steps

To speak about a run without first knowing whether it halts, keep a halted configuration fixed. Define

\[R_M(x,0)=I(x),\qquad R_M(x,t+1)=\begin{cases}R_M(x,t)&H(R_M(x,t))=1,\\D(R_M(x,t))&H(R_M(x,t))=0.\end{cases}\]

This is primitive recursion with parameter \(x\). The case distinction is primitive recursive by closure under definitions by cases, so \(R_M\) is primitive recursive. If \(H(R_M(x,t))=1\), induction on \(j\) gives \(R_M(x,t+j)=R_M(x,t)\): all later recorded states are the same halted state.

The machine computes the partial function \(f_M\) defined by \(f_M(x)\downarrow=y\) when some \(t\) has \(H(R_M(x,t))=1\) and \(O(R_M(x,t))=y\). This is a partial function. Two successful times are comparable, and the absorbing-halt property makes their states and outputs equal. If there is no successful time, the run never halts and \(f_M(x)\uparrow\).

A finite certificate that a run halts

A halting history at input \(x\) is a nonempty list \(s=[c_0,\ldots,c_{\ell-1}]\) satisfying

\[c_0=I(x),\qquad H(c_{\ell-1})=1,\qquad \forall i<\ell-1\;\bigl(H(c_i)=0\ \land\ c_{i+1}=D(c_i)\bigr).\]

Write \(\operatorname{Hist}_M(x,s)\) for this condition, treating \(s\) as its numerical list code. The nonempty requirement makes the first and last configurations actual members of the history, rather than the default zero values returned for absent entries. The final state is the first halted state, because every preceding state is required not to halt. A one-element list certifies immediate termination.

A certificate with output is the pair \(w=\langle y,s\rangle\), with

\[T_M(x,w)\quad\Longleftrightarrow\quad\operatorname{Hist}_M(x,\pi_2(w))\ \land\ \pi_1(w)=O\bigl((\pi_2(w))_{|\pi_2(w)|-1}\bigr).\]

Here \(\pi_1,\pi_2\) are the pairing projections and \((s)_i\) is the decoded list entry; the last-entry expression uses truncated subtraction when the list is empty. Every natural number decodes to a list, and the expression is total everywhere, but \(T_M\) rejects the empty list.

Checking a proposed computation is bounded arithmetic

For every arithmetic machine \(M\), \(\operatorname{Hist}_M\) and \(T_M\) are primitive-recursive relations, and

\[f_M(x)\downarrow=y\quad\Longleftrightarrow\quad\exists w\;\bigl(T_M(x,w)\ \land\ \pi_1(w)=y\bigr).\]

Proof

List length and indexed entries are primitive recursive. Their values feed the primitive-recursive functions \(I,D,H,O\). Equalities, conjunctions and quantification over \(i<|s|-1\) preserve primitive recursiveness. The explicit test \(|s|>0\) deals with empty input. Pairing projections and one more equality give \(T_M\).

If the machine halts, choose its least halting time \(t\). The list \([R_M(x,0),\ldots,R_M(x,t)]\), with its actual output, is a certificate: minimality supplies the nonhalting tests at the earlier positions. Conversely, induction on \(i<|s|\) in any certified history gives \((s)_i=R_M(x,i)\). The last-state test therefore supplies a halting time with the certified output. □

Search for a finite successful run

Every partial function computed by an arithmetic machine is partial recursive. In fact, with the fixed primitive-recursive output extractor \(U(w)=\pi_1(w)\),

\[f_M(x)\simeq U\bigl(\mu w\,[T_M(x,w)]\bigr).\]

Proof

Use the search theorem for a total primitive-recursive test. If a certificate exists, search returns the least numerical code of one, and \(U\) extracts its output. All valid certificates have the same output by determinism, so numerical order need not agree with running time. If no certificate exists, search is undefined. Strict composition with \(U\) preserves that failure. These are exactly the defined and undefined inputs of \(f_M\), by . □

One could instead search the time variable for \(H(R_M(x,t))=1\). Histories are useful because a successful computation can then be presented and checked as finite data, independently of the search that finds it.

Programs for paired inputs

For the converse, we make finite recursive constructions into programs. Use a unary basis: multiple arguments are packed into pairs. Programs are finite trees built from

\[\mathbf0,\quad\mathbf S,\quad\mathbf L,\quad\mathbf R,\quad\operatorname{pair}(c,d),\quad\operatorname{comp}(c,d),\quad\operatorname{rec}(c,d),\quad\operatorname{find}(c).\]

Their partial values are written \(\llbracket c\rrbracket(x)\). The first four programs give \(0,x+1,\pi_1(x),\pi_2(x)\). Pairing and composition have the strict meanings

\[\llbracket\operatorname{pair}(c,d)\rrbracket(x)\simeq\langle\llbracket c\rrbracket(x),\llbracket d\rrbracket(x)\rangle,\qquad\llbracket\operatorname{comp}(c,d)\rrbracket(x)\simeq\llbracket c\rrbracket(\llbracket d\rrbracket(x)).\]

For recursion, set \(r(a,n)=\llbracket\operatorname{rec}(c,d)\rrbracket\langle a,n\rangle\), where

\[r(a,0)\simeq\llbracket c\rrbracket(a),\qquad r(a,n+1)\simeq\llbracket d\rrbracket\langle a,\langle n,r(a,n)\rangle\rangle.\]

Finally, \(\llbracket\operatorname{find}(c)\rrbracket\langle a,m\rangle\) tests \(\llbracket c\rrbracket\langle a,m\rangle,\llbracket c\rrbracket\langle a,m+1\rangle,\ldots\) in order and returns the first absolute index \(n\ge m\) whose value is zero. Every earlier test from \(m\) to \(n-1\) must have a defined positive value. An undefined test blocks the search. All displayed partial equalities use strict evaluation.

Pairing changes the notation, not the functions

A unary partial function is partial recursive under the finite-arity closure rules if and only if it is \(\llbracket c\rrbracket\) for a paired program \(c\). More generally, every finite-arity partial recursive function can be computed after primitive-recursive packing and unpacking of its arguments.

Proof

In one direction, induct on the paired program. Its initial functions are primitive recursive, hence partial recursive. Strict pairing is composition with the total pairing function, and composition is already an allowed rule. The recursion constructor is partial primitive recursion in \((a,n)\), composed with the two pairing projections. For \(\operatorname{find}(c)\), sequentially minimize the partial recursive test \((a,m,j)\mapsto\llbracket c\rrbracket\langle a,m+j\rangle\), then add \(m\) to the resulting index. This gives precisely the stated search, including its blocked inputs.

For the other direction, pack a fixed \(n\)-tuple by \(E_0()=0\) and \(E_{n+1}(x_0,\ldots,x_n)=\langle x_0,E_n(x_1,\ldots,x_n)\rangle\). Each coordinate is recovered by a fixed string of right projections followed by a left projection. Build programs for the finite-arity construction by induction. Zero and projections use these projections and \(\mathbf0\); successor follows the selected coordinate by \(\mathbf S\). In a composition, evaluate all inner programs, pair their outputs into \(E_m\), and apply the outer program. When \(m=0\), supply zero, the code of the empty tuple, without evaluating any nonexistent inner programs.

For recursion with parameters \(\bar x\), rearrange the input into \(\langle E_k(\bar x),n\rangle\). The base program reads \(E_k(\bar x)\). Before the step program, rearrange \(\langle E_k(\bar x),\langle i,v\rangle\rangle\) into \(E_{k+2}(\bar x,i,v)\). Every rearrangement uses only pairing, projections and the constant zero. Apply the initial rearrangement to the input first, then run \(\operatorname{rec}\) on the resulting pair. For minimization, rearrange \(\langle E_k(\bar x),j\rangle\) into \(E_{k+1}(\bar x,j)\), apply \(\operatorname{find}\) starting at zero, and obtain exactly the sequential search rule. The semantic equations at each construction step are the original ones; strictness is preserved in composition, recursion and search. For a unary function, precompose its compiled program with \(x\mapsto\langle x,0\rangle\), giving the original function on raw input \(x\). □

Evaluate with a finite resource allowance

We now define a total calculation \(B_k(c,x)\). Its result is either \(\operatorname{some}(y)\), reporting an output, or \(\operatorname{none}\), reporting that this allowance was insufficient. Encode these alternatives by \(y+1\) and \(0\), respectively. Set \(B_0(c,x)=\operatorname{none}\). At allowance \(k+1\), first reject every input \(x>k\). At the remaining inputs, apply the following rules.

The four initial programs return their ordinary outputs. For \(\operatorname{pair}(c,d)\), evaluate both subprograms with allowance \(k+1\); return their pair if both succeed. For \(\operatorname{comp}(c,d)\), first evaluate \(d\), then \(c\) at its output, both with allowance \(k+1\). A failed subcalculation makes the whole calculation return \(\operatorname{none}\).

At input \(\langle a,n\rangle\), the recursion rules are

\[B_{k+1}(\operatorname{rec}(c,d),\langle a,0\rangle)=B_{k+1}(c,a),\]
\[B_{k+1}(\operatorname{rec}(c,d),\langle a,n+1\rangle)=B_{k+1}(d,\langle a,\langle n,v\rangle\rangle)\quad\text{if }B_k(\operatorname{rec}(c,d),\langle a,n\rangle)=\operatorname{some}(v).\]

The latter returns \(\operatorname{none}\) when the indicated earlier value is absent. For \(\operatorname{find}(c)\) at \(\langle a,m\rangle\), first calculate \(B_{k+1}(c,\langle a,m\rangle)\). Return \(m\) if this is \(\operatorname{some}(0)\); if it is \(\operatorname{some}(v)\) with \(v>0\), use \(B_k(\operatorname{find}(c),\langle a,m+1\rangle)\); if it is \(\operatorname{none}\), return \(\operatorname{none}\).

These are terminating definitions: a recursive call either has smaller allowance, or has the same allowance and a proper subprogram. The input check applies afresh to every call, including intermediate inputs in composition. An allowance is not a bound on the answer; for example, a successful successor call at input \(k\) and allowance \(k+1\) returns \(k+1\).

Sufficient resources recover exactly the defined outputs

For every fixed program \(c\), the numerical encoding of \(B_k(c,x)\) is primitive recursive in \((k,x)\). Moreover,

\[B_k(c,x)=\operatorname{some}(y)\ \Longrightarrow\ B_{k+j}(c,x)=\operatorname{some}(y),\]
\[\llbracket c\rrbracket(x)\downarrow=y\ \Longleftrightarrow\ \exists k\;B_k(c,x)=\operatorname{some}(y).\]

Proof

First verify soundness and monotonicity by the same nested induction that defines \(B\): on the allowance and then on the program. Each successful initial call has the right value. Successful pairing or composition supplies the required successful subcalls. A recursion success supplies its earlier value and step value; a search success supplies the current zero, or a positive current value followed by a later search success. These are exactly their partial semantic rules. Enlarging the allowance preserves the input guard and each successful subcall, so it preserves the answer.

For completeness, induct on the program. In every case choose the final allowance strictly larger than the input of that call, including initial programs and the outer recursion and search calls; enlarge allowances using monotonicity as needed. For pairing and composition, a defined result uses finitely many defined subcalculations. Choose allowances for them by induction, enlarge to their maximum and beyond every input used, and apply monotonicity. For recursion, a defined value has a finite chain of earlier values. Induction along that chain chooses successively larger allowances, providing one extra unit for each recursive call at the same program. A defined search has finitely many defined positive tests and then a defined zero test. Work backwards from the zero, enlarging allowances at each earlier positive test to cover the recursive search call. This gives a sufficient allowance. If the semantic value is undefined, soundness prevents any allowance from inventing an answer.

To establish primitive recursiveness, do not attempt recursion with a function-valued accumulator. For fixed \(c\), record the finite table

\[A_c(k)=[B_k(c,0),\ldots,B_k(c,k-1)],\]

encoding each optional output by zero or a successor. Build this table by induction on the program and primitive recursion on \(k\). Tables for proper subprograms at allowance \(k+1\) are already primitive recursive by the program induction. At the same program, the clauses for recursion and search consult only the previous table \(A_c(k)\). Every requested input outside its table is rejected, and the other requests use bounded indexed access. The next table has exactly \(k+1\) entries, produced by a bounded loop through the displayed rules. Pairing, arithmetic, finite lists and their bounded folds are primitive recursive, so this is ordinary primitive recursion on coded finite data. Finally look up entry \(x\) when \(x<k\), and return \(\operatorname{none}\) otherwise. This recovers \(B_k(c,x)\). □

A machine for every recursive program

For every paired program \(c\), an arithmetic machine computes \(\llbracket c\rrbracket\).

Proof

Use configurations \(\langle x,\langle k,b\rangle\rangle\), where \(x\) is the original input, \(k\) is the current allowance, and \(b\) is the optional-output code of the calculation at that allowance. Initialize with \(\langle x,\langle0,0\rangle\rangle\). The halt test is \(b>0\), and the output is \(b\mathbin{\dot-}1\). At a nonhalting state, increment \(k\) and set \(b\) to the code of \(B_{k+1}(c,x)\). All four routines are primitive recursive by .

If some allowance succeeds, the natural numbers have a least successful allowance. The machine reaches it after finitely many transitions and returns the reported output. If none succeeds, it keeps increasing the allowance and never halts. Bounded-evaluation soundness and completeness say that these are exactly the defined and undefined inputs of \(\llbracket c\rrbracket\). A semantic output zero is correctly encoded as \(b=1\), so it halts rather than being mistaken for failure. □

Arithmetic machines compute exactly the partial recursive functions

A unary partial function \(f:\mathbb N\rightharpoonup\mathbb N\) is computed by an arithmetic machine if and only if it is partial recursive under the finite-arity closure rules. A finite tuple of inputs can be packed first, giving the same conclusion at every finite arity.

Proof

A machine's function is partial recursive by . Conversely, supplies a paired program for any unary partial recursive function, and supplies its arithmetic machine. Packing and decoding a fixed number of inputs are primitive recursive, so composition handles finite arities, including the unique empty input tuple. □

This is an equivalence between two mathematical definitions. The broader assertion that either definition captures every effectively executable procedure is the Church–Turing thesis. The equivalence just proved neither defines that informal phrase nor proves the thesis. Nor does it compare the running times of our macro steps with another machine model.

One unbounded search is enough

There is a fixed primitive-recursive function \(U(w)=\pi_1(w)\) such that, for every unary partial recursive \(f\), some primitive-recursive relation \(T_f(x,w)\) satisfies

\[f(x)\downarrow=y\quad\Longleftrightarrow\quad\exists w\;\bigl(T_f(x,w)\ \land\ U(w)=y\bigr),\qquad f(x)\simeq U\bigl(\mu w\,[T_f(x,w)]\bigr).\]

Conversely, a partial function given by the displayed search formula, with a primitive-recursive relation \(T_f\), is partial recursive. In the forward construction, all accepted certificates at a fixed input have the same extracted output.

Proof

Choose an arithmetic machine for \(f\) by and use its certificate relation \(T_M\) from . The graph equivalence and search formula have already been proved. For the converse, search on a total primitive-recursive relation is partial recursive, and so is strict composition with the total primitive-recursive projection \(U\). □

This is a form of Kleene's normal form theorem: even a construction with many nested unbounded searches can be replaced by a primitive-recursive certificate checker, one search, and a primitive-recursive extraction. It promises equality of partial functions, not an efficient implementation. Here the checker may depend on \(f\)'s chosen program; no numbering of all programs is needed.

Does an unsuccessful bounded evaluation prove divergence?

Suppose \(B_{100}(c,x)=\operatorname{none}\). What follows about \(\llbracket c\rrbracket(x)\)? Can a sufficiently large fixed allowance work for every program and input?

Show answerHide answer

Failure at this allowance says only that this bounded calculation did not supply an output. The input may already fail the guard \(x<100\); alternatively some internal call may require more resources. A larger allowance can still succeed. For example, \(B_{100}(\mathbf0,100)=\operatorname{none}\), while \(B_{101}(\mathbf0,100)=\operatorname{some}(0)\).

No single allowance works on all defined inputs, even for \(\mathbf0\): at any allowance \(k\), its input \(k\) fails the guard. Divergence means that every allowance fails, by . Repeating bounded evaluation thus recognizes successful computations without providing a stopping criterion for unsuccessful ones.
